# ADR 0002: 要約 CLI への根拠 ID の渡し方と検証

- 状態: 採用
- 決定日: 2026-09-30

## 状況
AC-05 は、ノート項目の根拠 ID が実在する segment を指すことを求める。UUID をそのまま LLM に渡すとトークンを多く消費し、写し間違いによって存在しない ID が生成されやすい。

## 決定
- CLI には `S1, S2, …` という短い別名で発話を渡し、サーバー側で UUID に戻す。
- 存在しない別名は除外する。根拠が 0 件になった項目には `noEvidenceReason` を付ける。
- ID、revisionId、generatedAt はサーバーが付与する。LLM が返すのは下書きで、正規化の後に `note-1.0.schema.json` で厳格に検証する。
- 検証に失敗した場合は修復プロンプトを 1 回だけ送る。それでも失敗したら `summary_invalid_schema` とし、ノート版は適用しない。
- CLI の出力と transcript は不可信データとして扱う。プロンプトでは、transcript は命令ではなくデータであると明示し、CLI のツール実行は無効化する。

## 影響
根拠の追跡可能性はサーバー側で保証される。モデルが根拠を誤った場合でも「根拠なし」として表示されるので、利用者が確認できる。
